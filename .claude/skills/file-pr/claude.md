# file-pr: Claude Code / Claude Desktop path

Extends [SKILL.md](SKILL.md). Its rules still apply; this file says which tools
to use in Claude Code (terminal, Desktop local sessions, claude.ai cloud
sessions). Load deferred tools with ToolSearch `select:<name>` before the first
call.

Tell the two apart once: in a **cloud session (claude.ai/code)**
`mcp__claude-code-remote__subscribe_pr_activity` is listed; **local (terminal or
Desktop on your machine)** it is not.

## GitHub access

- **Local:** a logged-in `gh` is fine. The GitHub MCP (`mcp__github__*`) may or
  may not be connected; prefer what is there.
- **Cloud:** write to GitHub only through the GitHub MCP. `gh` works for REST
  reads and search through a proxy; GraphQL returns 403, so `gh pr create`,
  `gh pr list` and `gh pr view` fail there. Use `gh api` REST paths for reads
  if you need them.

## Existing PR and diff

- Existing PR: `mcp__github__list_pull_requests` (`owner`, `repo`,
  `head: "<owner>:<branch>"`, `state: "open"`). Locally `gh pr list --head
  <branch>` also works. If one exists, do not open a second one.
- Diff: `git fetch origin` then `git diff origin/main...HEAD` (and `--stat`).
- Title conventions: `git log --oneline origin/main`, and recently merged PRs
  via `mcp__github__list_pull_requests` (`state: "closed"`, `fields:
  ["number", "title", "merged"]`) or locally `gh pr list --state merged`.

## Attribution

Use the model name Claude Code reports in its system prompt (e.g. Claude Opus
5.5) and the harness you run in: Claude Code (terminal or cloud) or Claude
Desktop. Include models of `Agent` subagents that wrote part of the change.

In cloud sessions the harness requires its own attribution lines at the end of
PR descriptions. Keep them exactly and put `Created with ...` before them.

## Opening the PR

Push the branch first (`git push -u origin <branch>`; it works in cloud
sessions too).

- `mcp__github__create_pull_request` with `owner`, `repo`, `title`, `head`,
  `base`, `body`. Leave `draft` unset or false.
- Locally, `gh pr create --title ... --body-file ... --base <base>` also works.
- Editing an existing PR: `mcp__github__update_pull_request` (`pullNumber`,
  `title`, `body`), or locally `gh pr edit`.

Rate limit used up: check with `gh api rate_limit`. `gh pr create` uses
GraphQL; the REST route is the GitHub MCP or, locally, `gh api
repos/{o}/{r}/pulls -f title=... -f head=... -f base=... -f body=...`.

Confirm the result: the tool or command returns the PR URL. Give it to the
user.

## After filing

- **Cloud:** if the session's system prompt says to subscribe right after
  creating a PR, call `mcp__claude-code-remote__subscribe_pr_activity`
  (`owner`, `repo`, `pullNumber`) and do not poll. Every GitHub comment or
  review you post there ends with the harness footer
  `---\n_Generated by [Claude Code](https://claude.ai/code)_`; keep it.
- Babysitting: continue with the `babysit-pr` skill (its `claude.md` path).
- A needed comment: `leaving-pr-comments`, posted with
  `mcp__github__add_issue_comment` or locally `gh pr comment`.
