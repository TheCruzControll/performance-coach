# leaving-pr-comments: Claude Code / Claude Desktop path

Extends [SKILL.md](SKILL.md); its rules still apply. This file says which tools
to use in Claude Code (terminal, Desktop local sessions, claude.ai cloud
sessions). Load deferred tools with ToolSearch `select:<name>` before the first
call.

Tell the two apart once: in a **cloud session (claude.ai/code)**
`mcp__claude-code-remote__subscribe_pr_activity` is listed; **local (terminal or
Desktop on your machine)** it is not.

## Header values

- `<model>`: the model name your system prompt states, e.g. Claude Opus 5.5,
  Claude Fable 5.1, Claude Sonnet 5.5, Claude Haiku 5.5. A subagent uses its
  own model, not the parent's.
- `<user>`: the user's name if they gave it, else their GitHub login from
  `mcp__github__get_me` (locally also `gh api user --jq .login`).

## GitHub access

- **Local:** a logged-in `gh` is fine. The GitHub MCP (`mcp__github__*`) may or
  may not be connected; prefer what is there.
- **Cloud:** post comments, replies and reviews only through the GitHub MCP.
  `gh` works for REST reads and search through a proxy; GraphQL returns 403. The proxy also offers
  `GET repos/{o}/{r}/pulls/{n}/ccr/review_threads` (thread resolution state) and
  `POST repos/{o}/{r}/pulls/{n}/ccr/comments/{id}/resolve`.

## Cloud footer

In cloud sessions the harness requires every GitHub comment or review Claude
posts to end with:

```md
---
_Generated by [Claude Code](https://claude.ai/code)_
```

Keep it, after the reply. It is the only allowed horizontal rule and footer;
do not add a second attribution. Locally, add no footer.

## Posting with the GitHub MCP

Find what to reply to with `mcp__github__pull_request_read` (`owner`, `repo`,
`pullNumber`): `method` `get_review_comments` (threads with resolved state,
thread node IDs and comment IDs), `get_reviews`, `get_comments`.

- Top-level PR comment: `mcp__github__add_issue_comment` (`issue_number` = PR
  number, `body`).
- Reply in a review thread: `mcp__github__add_reply_to_pull_request_comment`
  (`commentId`: the numeric ID from a `#discussion_r...` anchor, not the
  `PRRT_...` thread ID; `pullNumber`; `body`).
- Inline review comments: `mcp__github__pull_request_review_write` `method`
  `create` without `event` (pending review), then
  `mcp__github__add_comment_to_pending_review` per comment (`pullNumber`,
  `path`, `line`, `side`, `subjectType` `LINE` or `FILE`, `body`), then
  `pull_request_review_write` `method` `submit_pending` with `event` and
  `body`. Each inline comment and the review body get the note callout.
- Fix a posted top-level comment: `mcp__github__update_issue_comment`
  (`comment_id`, `body`). It cannot edit review comments.

Locally with `gh`: `gh pr comment <pr> --body-file <file>` for top-level
comments; `gh api repos/{o}/{r}/pulls/{n}/comments/{id}/replies -F body=@<file>`
for review replies. Write the body to a file so quoting and blank lines survive
the shell.

## Verifying and resolving

Each MCP call or `gh` command returns the created comment or review; confirm
its URL (`html_url`, or the URL `gh pr comment` prints) before going on. Then resolve the thread with
`mcp__github__resolve_review_thread` (`owner`, `repo`, `threadId`: the
`PRRT_...` node ID), or in cloud the `ccr/comments/{id}/resolve` proxy
endpoint, or locally `gh api graphql` `resolveReviewThread`.
