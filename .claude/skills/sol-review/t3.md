# sol-review: T3 Code path

Extends [SKILL.md](SKILL.md); its rules still apply. This file says which T3
tools to use.

## GitHub access

T3 Code runs Claude Code or Codex underneath: use whatever GitHub access that
session has (`gh` if logged in, or a GitHub MCP server).

## Load T3 tools

In Claude Code, T3 tools are deferred. Load them first with ToolSearch
`select:mcp__t3-code__orchestrator_capabilities,mcp__t3-code__delegate_task,mcp__t3-code__task_cancel`.
Elsewhere, if T3 tools are not listed, try one direct capability call.

## Start Sol

Call `orchestrator_capabilities`. If Sol is not listed, search `sol`.
Pick the latest Sol unless the user named a version. Do not hardcode an ID.
Prefer the `codex` provider instance. Set reasoning effort as SKILL.md says.
Use the effort option id that capabilities lists for that model
(`reasoningEffort` on codex), never a guessed one. Record provider, model, and
effort.

Use `delegate_task` every round (`role: "review"`, `mode: "async"`, `target`
with `providerInstanceId`, `model`, `options`). Keep `isolation` shared; a
worktree drops uncommitted edits. Save `taskId`. New `clientRequestId` per
round. `childThreadId` is storage, not the next target. Do not use
`t3_thread_send`, `create_threads`, or `t3_thread_launch` for review.

T3 children get no history: send the full round 1 brief from SKILL.md.

Wait for the completion notice. Do not poll. On failure, cancel with
`task_cancel` (saved `taskId`), verify it stopped, then restart with a fresh
`delegate_task` and the ledger.

## Next round

Use a fresh `delegate_task` (new `clientRequestId`) with the round 1 brief, the
ledger, the same base diff, and the change since last round.

## PR description

Edit the PR description with whatever GitHub access the session has (`gh pr
edit`, or the GitHub MCP if connected).
